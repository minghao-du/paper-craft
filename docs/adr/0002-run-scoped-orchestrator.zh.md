# Run 范围的 Orchestrator 取代 Conductor

[English](0002-run-scoped-orchestrator.md)

[规格 #71](https://github.com/minghao-du/paper-craft/issues/71) 的架构决策。

## 权限

**Orchestrator** 是一个 Run 唯一的调度权限主体，由恰好一个活跃的 **Orchestrator attempt** 实现，即属于该 Run 的受管执行。替换时保留历史尝试，且必须先验证旧尝试已经终止；占用状态未知时禁止复用。在具备显式注册机制之前，交互会话不能持有此权限。

**Fleet** 是包含多个 Run 和工作目录的配置与资源边界，自身没有调度代理。操作者输入决定跨 Run 的优先级；Run Registry 通过确定性规则仲裁预留、锁和所有权。**Coordinator** 负责组织 Project 范围的研究报告，不是 Run 调度者。

Provider 在 Run 接入时记录一次，之后从该 Run 读取。缺失、不支持或不匹配的 provider 必须明确报错。受管启动、检查和恢复都必须指定 Run；批量恢复调用同一条逐 Run 恢复路径。没有 Run 所有权的旧工作应报告为阻塞，绝不自动恢复。

## 直接切换

删除 Fleet 范围的 Conductor、其 CLI 命令组、运行时 API、技能名称和全局记录路径。不提供兼容入口、旧记录运行时读取兼容或弃用过渡期。旧全局记录由操作者归档，绝不接管。不交付迁移命令：切换前提是单一操作者，且没有进行中的 Run 或旧执行尝试。

先落实行为变更，再进行机械重命名。Run Registry 的 schema 保持不变。Dashboard 重设计、Fleet/Run 技能内容拆分以及交互会话注册另行处理。

## 未采纳的方案

- 将 Conductor 保留为交互角色，会在缺乏注册契约时保留两套竞争的所有权术语。
- 弃用过渡期会延续重复入口和兼容分支。
- 保留 Fleet 范围的代理，会重新引入权限歧义和独立 Run 之间的互斥。

## 术语守卫

对已跟踪文件进行不区分大小写的扫描，检查已退役的 Conductor 术语。仅允许本 ADR 双语文件、守卫测试自身以及明确指定的迁移检查清单文件出现这些术语。历史 ADR 不可修改；若历史文件出现这些术语，应添加显式允许列表条目，而非编辑历史。扫描不包含 Git 历史、已忽略文件、未跟踪文件或依赖。CLI 帮助快照和技能目录/安装检查保护重命名后的公开接口。

## 操作者切换检查清单

运行新工作流之前完成以下步骤。在本流程之外保留备份位置和验证结果作为切换证据；任何前提无法验证时，停止切换。

1. 冻结派生操作，并在替换已安装技能链接之前结束活跃代理会话。
2. 停止恢复监视器，确认其不会在切换期间重新启动工作。
3. 备份工作流状态树，并记录备份位置。
4. 验证没有进行中的 Run，也没有旧全局 Conductor 记录或执行尝试。归档任何旧全局记录，不恢复或导入它们。
5. 删除过时的会话注册文件，避免向失效地址推送完成通知。
6. 切换到新版本，重新链接已安装技能，并移除所有旧名称链接。
7. 验证只安装了新技能名称，CLI 帮助与新命令接口一致，然后重启监视器并解除派生冻结。
