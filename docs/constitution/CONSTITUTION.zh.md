# paper-craft 项目宪章

[English](CONSTITUTION.md)

paper-craft 项目的开发原则。

## Agent 执行，人类掌舵

将执行自动化，直到需要判断的环节。执行者自主完成实现、测试和质量门禁。人类选择工作方向，并解决真正的歧义（设计问题、含糊的需求、架构权衡）。

## Skills 即产品

Skills 是当前项目的核心产品，也是人类与 agent 之间唯一的执行接口。Skill 文档是权威依据——所有能力、契约与流程门禁均直接以 skill 形式定义和交付。现阶段不维护也不交付任何 CLI 层。

## 质量门禁优先于人工审查

自动检查（`/pc-pr-review`）循环运行，直到全部通过。修复其指出的每项缺陷——不跳过，也不使用 `--no-verify`。但检查本身必须快速且可操作，而非流于形式。建议增加内容不等于发现缺陷。

## 尽早失败，解释清楚

配置错误、数据缺失和未构建的索引必须立即产生可操作的错误。真正的问题是配置错误时，绝不悄悄返回空结果。错误信息必须说明预期是什么、实际收到了什么。

## 默认精简

Agent 自主决定并落地此工具的变更，同时持续压缩规模。skill、AGENTS.md 或启动提示中的每一行，都要由加载它的每次会话支付上下文成本；这些上下文本应留给实际工作。

审查 agent（包括同伴）会提出增加内容的建议：另一种模式、另一项检查、另一条注意事项。单看都很便宜，叠加起来却会层层膨胀。只有能解决实际遇到的失败或满足当前需求时才增加内容。优先删除和简化。

更强的模型需要更少的指导。曾用于弥补较弱模型错误的文字，在错误消失后仍长期消耗上下文；当一条指令不再改变行为时，就删除它。
