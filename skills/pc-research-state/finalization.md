# EPIC finalization writing

Use this branch when Conductor supplies an EPIC's post-merge writing brief. Apply the
main skill's resolve, check, edit and verify steps; this file adds the handoff contract.

Require the designated Project coordinator, unique absolute research entry, coordinator-
provided or confirmed scientific judgments, original EPIC objective, verified PR/SHA
identities, specific runs/data/parameters, evidence and Pipeline receipt or confirmed
skip reason. Return unresolved scientific decisions to that coordinator. Conductor
routes the exchange; it does not acquire scientific authority.

The coordinator serializes writing to the shared Project research home across EPICs
and Fleets. Begin only after the prior writer returned and coordination is unambiguous.
Resolve the shared research entry rather than copying state into the audit checkout.
Verify whole-workspace ignore and tracked-file handling under the existing convention.
Keep raw evidence at source and live task progress in the task system.

Return the structured receipt in
[Conductor finalization](../pc-conductor/finalization.md), including changed report paths,
affected folder mappings and dependent reports pending verification or rerun,
integrated results, evidence status, pending disagreements and deferred updates. Every
requested update must be recorded or have a coordinator-accepted deferral that does not
violate EPIC acceptance. Required-delivery evidence gaps block closure. Unresolved
scientific questions may remain explicitly recorded; preserve plans, observations,
interpretations and conclusions as distinct kinds of knowledge.

**Done:** All requested updates are accounted for, navigation and local-only storage
are verified, and receipt limitations distinguish open research from missing delivery.

For a managed Run, accepted Pipeline disposition and verified EPIC closure are mandatory.
Runtime reserves the canonical report destination across Fleets and supplies a private
candidate path. Write and verify that candidate only; runtime publishes it atomically
and retains path, hash, revision and version attribution. Failed writing preserves the
prior report. Keep accepted delivery versions separate from observed repository versions,
and explicitly record unrelated concurrent changes, missing evidence and limitations.
A report is required even when the EPIC delivered infrastructure without scientific results.
