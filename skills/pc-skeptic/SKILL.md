# /pc-skeptic

Audit surprising, strong, or negative computational research results before follow-up work or theoretical explanations are built upon them. Find the simplest explanation for an unexpected finding.

## Core Audit Checklist

Execute these checks in strict order. Stop as soon as a concrete mechanism is identified:

### 1. Software Bugs & Mechanical Failures
- **Reproduce on a trivial synthetic case**: Construct an extreme case where the ground truth is mathematically certain. If the method fails on the trivial case, the issue is an implementation bug.
- **Input integrity**: Verify file paths, array orientations, 0- vs 1-based indexing, coordinate offsets, and unit conversions.
- **Git blame on critical paths**: Check if the surprising behavior coincides with a recent refactor or optimization.
- **Silent error swallowing**: Inspect stderr, try/catch blocks, and return codes for ignored warnings or non-converged optimizations.

### 2. Asymmetric Evaluation & Information Leaks
- **Scoring asymmetry**: Does the evaluation metric favor one method? (e.g., evaluating alignments using ancestor reconstructions generated by the same algorithm under test).
- **Condition equivalence**: Are hyperparameters, seeds, hardware, iteration counts, and preprocessing strictly identical across baselines?
- **Information leakage**: Does any condition inadvertently receive ground truth, test labels, or oracle statistics?

### 3. Plausibility of Effect Size
- **Extreme rates (0% or 100%)**: Usually indicate a mechanical bug or broken pipeline rather than a genuine scientific phenomenon. Suboptimal methods still win on easy edge cases by chance.
- **Orders-of-magnitude divergences**: Discrepancies of thousands of nats or log-likelihood units on similar data indicate incompatible normalization constants or differing scoring formulas.
- **Literature comparison**: If established external benchmarks show modest differences, a 30%+ divergence indicates a setup error in the local harness.

### 4. Root Assumption Tracing
- Map the dependency graph of assumptions leading to the result:
  `Claim -> Metric -> Loader -> Data preprocessing -> Upstream artifact`.
- Check if upstream intermediate artifacts were independently verified or if a flaw in an earlier step propagated downstream.

### 5. Occam's Razor
Prioritize simple explanations over novel discoveries:
- A buggy scoring metric is simpler than "the algorithm class is fundamentally broken".
- Unfair parameter tuning is simpler than "established theory fails here".

## Verdict Format

Deliver an audit summary structured as:
- **Claim**: Exact statement of the surprising result.
- **Surprise Level**: Routine / Notable / Extraordinary.
- **Identified Concerns**: Ordered list of concrete discrepancies, bugs, or asymmetries found in code or configuration.
- **Validation Test**: Exact command or synthetic experiment to confirm or refute each concern.
- **Verdict**:
  - `[CREDIBLE]`: No methodological flaws found; result is trustworthy.
  - `[CHECK FIRST]`: Specific suspected flaws must be checked before building on this result.
  - `[SUSPECT]`: Fatal bug or asymmetry confirmed; do not pursue follow-up work based on this finding.
